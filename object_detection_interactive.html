Object detection, visually: single-stage (S2), two-stage (S3), NMS and mAP

Every tab uses the same cartoon image (cat, dog, car, bird), so you can see what each architecture actually does to a real picture.

The task: image in, a list of boxes out (and the list can be any length)

A classifier outputs one label per image. A detector must output, for each object: a box (x, y, w, h) plus a class distribution. The lecture names two problems:

  1. Variable number of outputs. This image has 4 objects; the next might have 0 or 40. A neural network's output has a fixed size.
  2. Where to look. Objects can be at any position and any scale (the bird is tiny, the car is big).
Both families solve problem 1 the same way: predict a large fixed number of candidate boxes (most of them "background" or low-score), then throw most away. They differ on problem 2:
  • Single-stage (OverFeat, SSD, YOLO): every grid cell of the feature map directly predicts boxes + classes in one pass.
  • Two-stage (R-CNN family): first propose "object-like" regions, then classify each one and refine its box.

IoU threshold: 0.5

IoU is used twice: to score a detection (it counts as a hit if IoU > 0.5, tab 7) and inside NMS (drop a box if its IoU with a better box is above the threshold, tab 3).

The R-CNN family: each version fixes the previous one's bottleneck

Why R-CNN is slow: the same pixels get convolved over and over

number of region proposals

Selective search (non-learned, slow at 1+ s per image) returns thousands of boxes, mostly background or object parts. R-CNN warps each one to the CNN input size and runs the whole CNN on it. The overlaps mean the same convolution on the same pixels is recomputed many times; that's the waste Fast R-CNN removes.

Mask R-CNN: Faster R-CNN + "which pixels inside the box are the object?"

ROI:  

For each ROI the mask head outputs a small grid (here 28×28, as in the paper) of foreground/background probabilities. The box alone says "cat around here"; the mask says which pixels are the cat and which are grass. That makes it instance segmentation.

Losses: RPN objectness, RPN box, head class, head box (the 4 from Faster R-CNN) + mask loss. Slide 39 shows RoIAlign: a version of ROI pooling that skips rounding to whole cells. It matters for pixel-accurate masks; the lecture doesn't go into it.

ROI pooling: any size region → fixed-size grid (so the FC layers can take it)

ROI:   output grid:  (or click-drag on the image to draw your own ROI)
① ROI in image pixels
② projected onto the 14×14 feature map (stride 32), split into bins
③ max of each bin = fixed output
Step by step: (1) Divide the ROI's image coordinates by the backbone stride (32 here) to find its feature-map cells; this works because each feature-map cell has a known receptive field. (2) Lay a fixed grid (e.g. 4×3) over that region. (3) Max-pool each bin. Different ROIs give regions of different sizes, but the output is always 4×3. Backprop routes the gradient to the max cell of each bin, as in max pooling. Try the bird (tiny) and the car (big).

Four losses: ① RPN objectness, ② RPN box refinement, ③ head classification over categories, ④ head box refinement. Why anchors? This is the same trick as SSD: a fixed grid × k fixed boxes gives a fixed-size output, which solves the variable-count problem. Non-differentiable part: moving a proposal changes which features get cropped into ROI pooling, so the gradient w.r.t. the box coordinates isn't well defined. One fix is to alternate between training the RPN and the head.

From detections to AP to mAP (slide 28)

Class:   IoU threshold for a hit:

score threshold (operating point)

AP = (1/11) Σr ∈ {0, 0.1, …, 1} pinterp(r),   pinterp(r) = max precision at any recall ≥ r     mAP = mean of AP over classes
Recipe: ① Sort the class's detections by score. ② Walk down the list: a detection is a TP if IoU > threshold with a ground-truth box that hasn't been claimed yet; otherwise it's an FP (bad box, duplicate, or background). ③ After each row: precision = TP/(TP+FP) and recall = TP/(#GT). ④ Read precision at the 11 recall levels. Taking "max precision to the right" is the standard VOC interpolation; the lecture just says "precision at recall 0, 0.1, …, 1". ⑤ Average the APs over classes to get mAP. Switching to IoU 0.75 shows that sloppy boxes turn into FPs.
