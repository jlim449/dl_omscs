Normal conv vs transposed conv (slide 14)

Normal convolution (encoder)Transposed convolution (decoder)
one stepdot product of kernel and an input patch → 1 output value1 input pixel × whole kernel → a k×k stamp on the output
overlapspatches overlap in the input (inputs get reused)stamps overlap in the output, and overlapping values are summed
size (stride 1)H − k + 1 (shrinks)H + k − 1 (grows)
general size⌊(H − k + 2p)/s⌋ + 1(H − 1)·s + k − 2p
stride meansmove the patch s pixels in the inputmove the stamp s pixels in the output for each input pixel step (upsamples about ×s)
padding meansadd p zeros around the inputcrop p rows/cols off each side of the full output
outfull(r, c) = Σi,j X(i, j) · K(r − s·i, c − s·j)   (terms where the K index falls outside the kernel are dropped)   →  out = outfull[p : −p, p : −p]

Read it as "input pixel (i,j) puts its stamp with top-left corner at (s·i, s·j); kernel cell (a,b) lands on output (s·i + a, s·j + b)."

Output-size calculator

Sanity check: a transposed conv with (k, s, p) maps H back to the size that a normal conv with the same (k, s, p) would shrink from. That's why decoders mirror encoders. Example: conv k=4, s=2, p=1 takes 8 to 4, and transposed conv k=4, s=2, p=1 takes 4 to 8.

Recipe for exams

  1. Size first: full output = (H−1)·s + k per side. Draw an empty grid of that size.
  2. For each input pixel (i,j) in reading order: multiply the whole kernel by X(i,j) and add it into the grid with its top-left at (s·i, s·j).
  3. Sum overlaps (they happen only when k > s; if k < s there are zero gaps).
  4. Crop p from every side if there is padding.
  5. Spot-check one cell with the gather formula: out(r,c) = Σ X(i,j)·K(r−s·i, c−s·j).
Do NOT flip the kernel in the stamp method: kernel cell (0,0) goes to the stamp's top-left. A flip only appears when you rewrite it as a normal cross-correlation (tab 3). The lecture also mentions a non-learned variant: the decoder uses the encoder's conv kernel rotated 180°. That's a choice of which K to use; the computation itself is unchanged.

Stamp method: step through the input pixels

Click an input pixel to jump to its stamp. Cells hatched red are cropped by padding p. Each output cell lists the stamps that have landed on it so far.

Compute one output cell directly (the fast way to answer "what is out(r,c)?")

out(r, c) = Σi,j X(i, j) · K(r + p − s·i,  c + p − s·j)

Click an output cell. Highlighted input pixels are the ones whose stamp covers this cell. Each is labeled with the kernel entry it uses. To find them: for each input pixel, check whether 0 ≤ r+p − s·i < k (and the same for columns).

The same result as a normal stride-1 cross-correlation

  1. Zero-insert: put s−1 zeros between the input pixels (this is why it's also called a "fractionally strided" conv, stride 1/s).
  2. Pad with k−1 zeros on every side.
  3. Rotate K by 180° and slide it with stride 1 (an ordinary cross-correlation).
  4. Crop p from each side.

This is exactly the "pad dout, rotate W, cross-correlate" recipe for ∂L/∂X from M2L6 S2 (B4). Click an output cell.

Why it's called "transposed": out = Cᵀ · x

Write a normal conv (kernel K, stride s, going from the big map to the small map) as a matrix: y = C·z, with z flattened. The transposed conv is out = Cᵀ·x, the same matrix transposed, mapping small back to big.

  • Column j of Cᵀ is input pixel j's stamp: the kernel laid out in the output. Click a column header.
  • Row r of Cᵀ lists which input pixels feed output cell r, and through which kernel weight (gather). Click a row header.
  • Cᵀ undoes the shape change, not the values: C·(Cᵀx) ≠ x in general, so it isn't an inverse. "Deconvolution" is a misleading name.
