The key idea: the same double sum, two loop orders

Near the current weights the loss changes by Σr,c G(r,c)·y(r,c). Substituting the forward pass makes every term a (d, w, x) triple:

Σr,c Σa,b  G(r,c) · k(a,b) · x(r+a, c+b)
PDF rule: loop over windows (scatter)S2 formula: loop over the variable (gather)
∂L/∂Wfor each window k:   ∂L/∂W += dk · windowkfor each k(a′,b′):   Σr,c G(r,c) · x(r+a′, c+b′)
∂L/∂Xfor each window k:   ∂L/∂X[patch k] += dk · Wfor each x(r′,c′):   Σa,b G(r′−a, c′−b) · k(a,b)

Fix (a,b) and sum over (r,c): ∂L/∂k. Fix the pixel r+a=r′, c+b=c′ and sum over everything that lands on it: ∂L/∂x. The PDF and S2 compute the same sum. The PDF goes window by window; S2 collects the terms for one variable at a time.

The master table: the PDF's y-equations, one row per window

Row k is y_k = (pixel)·w₁ + (pixel)·w₂ + … from the PDF. Each cell is the input pixel that weight multiplies in that window, i.e. ∂yk/∂wi. Click a column header to get ∂L/∂w (multiply the column by d and sum: Part A). Click a cell to get ∂L/∂x for that pixel (collect every cell holding the same pixel: Part B).

Forward pass: S2 setup ↔ PDF section 1

Click an output cell. The colored input cells are its receptive field; each color is the weight that pixel is multiplied by.

Bridge: the window is ∂y/∂W. The forward pass is linear in the weights, so the window entry under wi is ∂yk/∂wi. S2 writes this as ∂y(r,c)/∂k(a′,b′) = x(r+a′, c+b′). The PDF gets to it by writing out the window. Part A builds on this fact.

y vs dout: both have the same shape but mean different things

Bridge: S2 calls dout the "upstream gradient ∂L/∂y (known)". The conv layer receives it from the layers after it and does not compute it. Here it comes from the loss chosen in the toolbar. Switch to "custom G" to type it in yourself; S2's worked example does this.

View A: S2 gather. Pick one weight and collect from every output (A1–A3)

Click a cell of ∂L/∂W. The highlighted input pixels are x(s·r+a′, s·c+b′), the pixels that weight multiplied. Each one carries the d it is paired with. At stride 1 they form a block the shape of dout, shifted by (a′,b′). That is S2's "stride the upstream gradient across the input" (A3, cross-correlation of X with dout).

Implementation (S2 B4, PDF section 5): pad dout, rotate W by 180°, cross-correlate

∂L/∂x(r′,c′) = Σa,b G(r′−a, c′−b)·k(a,b)  =  Σa,b Gpad(r′+a, c′+b)·krot(a,b)

Click an output cell. The dashed window on padded dout slides like a forward pass. The rotated kernel puts w₄ top-left, so each d meets the same weight it met in View A.

Duality: the forward pass is cross-correlation, so the gradient w.r.t. the input is a convolution of dout with W. The minus sign in G(r′−a, c′−b) is the flip. A convolution is implemented as a cross-correlation with a rotated kernel, so the backward pass reuses the forward code.
